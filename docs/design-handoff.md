## 2. デザインの方針(変えないこと)

- **スターバックスのような落ち着いたトーン**:深緑と生成り、差し色はゴールド。装飾は最小限。
- **覚えてもらう要素は、ナビ画面の円形ダイヤル1つ**。他は静かに保つ。
- 両手がふさがる前提。**大きい文字・少ない操作**を最優先。
- 「注ぐ」と「待つ」は **文言と背景色の両方** で区別する(色だけに頼らない)。
- 「今回 +○ml」と「累計 ○mlまで」を **両方** 表示する。

## 4. 画面仕様

### 4.1 セットアップ
1. 緑のヘッダー:アプリ名、**豆(g)・お湯(ml)を大きく**表示、チップで挽き目・湯温・所要時間。杯数やレシピを変えると即時に数字が変わる(`aria-live="polite"`)。
2. レシピ選択:1枚の白いシートに縦並びのラジオリスト(名前+説明)。`role="radiogroup"` / `role="radio"`。
3. 杯数:1〜4の丸ボタン。
4. 注ぎ方:縦のタイムライン(開始時刻 / 工程名 / +今回 / 累計ml)。工程は順序があるので線と点を使ってよい。
5. 画面下に固定の主要ボタン「抽出をはじめる」。押下時に `initAudio()`(自動再生制限対策)。
6. 「確認用の再生速度」はモック専用。**本実装では削除**(開発時のみ有効にするなら環境フラグで)。

### 4.2 ナビゲーション(最重要)
上から:経過時間(`m:ss / 合計`)→ 工程名と「注ぐ/待つ」→ **円形ダイヤル** → 次の工程までの秒数 → 工程一覧 → 一時停止・中止。

ダイヤル(`viewBox 0 0 200 200`, 半径88, 線幅7):
- リング = **今の工程の経過**(`(elapsed - startSec) / (endSec - startSec)`、0〜1)。12時起点・時計回り・丸端、色はゴールド。
- 中央 = 累計ml(大)、「mlまで」、「今回 +○ml」(丸いチップ)。
- 大きさ:`min(72vw, 38dvh, 320px)`。高さ640px以下の端末では縮小。
- 状態は3つ:`pour`(深緑)/ `wait`(炭色)/ `fin`(濃い緑)。
- 工程一覧:今の工程だけ生成り地で浮き上がり、終わった工程は薄く表示。

**ダイヤルの挙動(議論して確定済み。変更しないこと)**
- リングは工程ごとに `key={idx}` で作り直す。次の工程へ進んだ時点で、**古いリングは残さず、0から伸ばし直す**。
- 以前、`stroke-dashoffset` のトランジション(0.2秒)が 100% → 0% で **逆再生のように巻き戻る** 不具合があった。`key` による作り直しで解消済み。
- 「尾が前向きに消える」演出も試して、ユーザー判断で **不採用**(切り替え時に古いリングが残るのが気になるため)。復活させない。
- 進行中の滑らかな動き用の `transition: stroke-dashoffset .2s linear` は維持。

### 4.3 完了
- 緑の全面、ゴールドの丸の中にチェックが描かれる(`stroke-dashoffset` アニメ、初回のみ)。
- 豆・お湯・抽出時間を一覧表示。
- 「同じ設定でもう一杯」(主要)と「設定に戻る」(補助)。

## 5. 共通の品質基準(モックで満たしているもの。維持すること)

- キーボード操作可能、フォーカス枠が見える(ゴールドの3px)。
- `prefers-reduced-motion` で全アニメーションを止める。
- 小さい画面(高さ640px以下)でダイヤルと工程一覧を詰める。
- セーフエリア(`env(safe-area-inset-*)`)を上下に反映。
- 文言は日本語・平易・能動。ボタンは動作をそのまま書く(「抽出をはじめる」「一時停止」「再開」「中止」)。

## 6. 本実装で直すべき点(モックの未対応・暫定)

優先度が高い順。

1. **画面スリープ防止の再取得**:Wake Lock はタブが非表示になると解除される。`visibilitychange` で再取得する処理がない(README 要件8に関わる)。
2. **フォントの自前配信**:現状は Google Fonts の CDN 読み込み。PWAのオフライン動作のため、サブセット化して同梱する。
3. **`confirm()` の置き換え**:中止の確認がブラウザ標準ダイアログ。アプリ内のダイアログ(大きなボタン)にする。
4. **長い工程名の折り返し確認**:4:6メソッドの「注湯1(甘さ・酸味)」などは、工程一覧・タイムラインの列幅(`1fr`)で折り返す可能性。実機で要確認。
5. **`before`(開始待ち)の分岐は死んでいる**:全レシピの先頭工程が 0 秒開始のため `hint` は出ない。残すか削るか判断する。
6. **`Navigate` の副作用の整理**:合図(`beep`)の効果が `[elapsed]` 依存で `eslint-disable` している。工程切り替えの検知を、関数化または専用フックに分けて見通しを良くする。
7. **完了時の `setTimeout`(1.2秒)**:画面遷移で中止されたときに解除されない。クリーンアップを入れる。
8. **「もう一杯」の挙動**:現状は直接ナビへ遷移。音声コンテキストは初期化済みだが、実機(特にiOS)で音が鳴るか確認する。
9. **`theme-color`**:画面ごと(セットアップ/ナビの状態)に変えるかは未決。現状は `#1e3932` 固定。
10. **レシピデータ**:割合の合計は3レシピとも100%。追加時は合計100%を保つこと(ミリ数は累計から丸めて差を出しているので端数は出ない)。

## 7. 本実装に引き継ぐ構成案(提案)

モックの `App.tsx` に状態が集まっている。次の分割を推奨(必須ではない)。

- `recipes.ts`:データと `calc()`。**そのまま流用可**(型・計算ともに設計通り)。
- `feedback.ts`:音・振動・Wake Lock。再取得処理を追加して流用。
- `useBrew()`(新規):経過時間・一時停止・工程判定をまとめたフック。タイマーは **開始時刻との差** で求める(README の方針どおり)。
- `Dial.tsx`(新規):円形ダイヤルを独立コンポーネント化。上記 4.2 の挙動を保つ。
- CSS:現状は1ファイル。分けるなら画面単位。トークンは `:root` のまま。

## 8. 確認の仕方

- `npm run dev` → セットアップ画面の「確認用の再生速度」を×5〜×10にすると、工程の切り替わりを短時間で確認できる(モック用)。
- 工程の切り替えでダイヤルが逆に動かないこと、古いリングが残らないことを、本実装でも必ず確認する。
